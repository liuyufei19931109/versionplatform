# 日常使用指南

平台按**服务 → 构建任务 → 制品 → 发布记录**组织工作。想从零跑第一单，可先按[接入第一个服务](first-service.md)配置一个独立的预生产节点。

## 按角色使用

| 要做的事 | 从哪里开始 |
| --- | --- |
| 初始化账号、给同事分配权限 | 管理员通过「基础配置」管理用户与菜单权限。每位用户首次登录按引导打开「登录安全」，选择「开始绑定」、扫描二维码并输入自己验证器的六位动态码。 |
| 接入代码、环境与节点 | 「服务管理」配置仓库、构建方式和启用的环境；「服务器管理」维护 SSH 连接和远端 Compose 项目。能修改构建或启动命令的用户应受信，因为这些命令会在构建机或目标节点执行。 |
| 构建新版本 | 「新建打包」选择服务与分支，核对 Commit。「仅打包」会保留制品；预选开发或预生产目标时，构建成功后会自动提交发布。关闭页面后任务仍会执行。 |
| 发布已有的成功构建 | 「新建发版」选择**平台内该服务的成功制品**、环境和目标节点，核对目标范围。已有任务或选中历史版本时，向导会提示再次核对。 |
| 查看执行记录与实际运行状态 | 「打包记录」「发版记录」按任务显示步骤、日志、操作人和结果。「运行总览」可以按节点检查当前容器和镜像，进入「服务日志」查看应用文件或容器标准输出。 |

## 选对构建方式

- **后端服务**在本机模式下先运行配置的应用构建命令，再用仓库 Dockerfile 生成镜像。按命令准备相应 JDK 与 Maven，或项目使用的 Gradle 工具链。构建机上的 Docker 需能执行构建和推送。
- **前端服务**支持静态站点和仓库 Dockerfile 两种方式。静态站点在构建机执行项目的 Node 构建命令，再将产物打入 Nginx 镜像。仓库 Dockerfile 模式由镜像内的步骤安装依赖和构建应用。
- **Flutter Android**从「App 发布」登记，在 App 构建配置中分别配置各环境的包名、签名、Flutter 版本和可选构建参数。选择本机构建时，应先准备 Flutter、Android SDK、JDK、签名及相应校验工具。APK/AAB 的外部交付需要拉取已锁定的安装包，完成实际分发后再确认结果。
- 本源码预览提供平台本体。GitHub 云构建依赖另行准备执行仓库、工作流与授权；小程序功能默认关闭。通用 Dockerfile 服务、从外部 CI 登记已有镜像、首次接入自检仍在规划中。

## 生产发布与回退

1. 第一次发生产前，先把**同一制品**发布到预生产，等待节点健康检查通过。只有已通过预生产或此前在生产成功发布的制品可进入生产流程。
2. 在「发版记录」从成功的预生产版本发起生产发布，或在「新建发版」选择对应制品。核对服务、版本、生产环境和节点，再使用**当前登录账号**绑定的动态码确认。生产任务失败后重试也要重新验证。
3. 需要回退时，从成功发布的历史制品中选回目标版本，并重新核对要切回的生产节点。保持镜像仓库中的历史标签与内容，避免覆盖或清理仍可能使用的镜像。当前版本按镜像引用拉取；按不可变摘要部署仍在规划中。
4. 发版记录表示某次操作的结果。判断节点**此刻**运行哪个镜像，应在「运行总览」重新检查。取消正在执行的任务只能阻止后续步骤，已经在目标节点执行的操作需要单独核实。

## 常见操作

- **修复构建失败**：在任务详情找到第一个失败步骤。网络或仓库暂时不可用，恢复后可重试。若改动了源码，需在「新建打包」重新选择并确认最新 Commit。
- **核对版本和分支**：「版本管理」可把多个服务与版本分支关联。当前版本计划以远程 `master` 为基准；打包时也会单独重新检查基线。生产自动合回默认关闭，启用后需单独授权 Git 写入并查看合回结果。
- **查看日志、更新配置**：「运行总览」按需读取节点状态；「更新配置并重启」会读取服务器当前 Compose 和环境配置，用现有镜像重建指定服务，造成短暂中断。先核对目标容器，生产操作还需验证动态码。
- **保管运行数据**：隔离测试和生产的仓库凭据、SSH 密钥、数据目录及镜像命名空间。把数据库、凭据加密密钥和动态码加密密钥作为同一套恢复资料备份；运行数据、签名文件、备份和真实日志均应存放在源码仓之外。
